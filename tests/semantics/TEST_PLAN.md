# IA-32 semantics test plan (dismount IR vs. the processor)

Goal: prove that the semantic IR of every lifted IA-32 instruction does exactly
what the processor does. Each instruction is executed twice from the same
random state:

1. **dismount**: decode the bytes, lift them with `IA32SemanticLifter`, run the
   IR with `SemanticInterpreter`.
2. **oracle**: run the same bytes on the Unicorn engine (QEMU's x86 CPU), in
   16-bit real mode or 32-bit protected mode.

The final registers, flags, written memory and the exit (fall through, branch,
trap) must be equal. The flags that the instruction leaves undefined
(`OpcodeClassification::getFlagsUndefined()`) are not compared.

Two C++ unit tests check the IR on its own (`tests/TestSemantics.cpp`, in
`test_dismount`):
- `SemanticInterpreter::evaluate()` and `evaluateFlags()` on hand-computed
  vectors, for every operation and recipe the interpreter implements.
- `run()` on hand-written blocks: labels and branches, sub-register aliases
  (al/ah/ax/eax), sub-register writes, traps, memory faults, helpers.

## `dismount_cli run`

```
dismount_cli run [--bits 16|32]
```

Each input line is `<hex bytes of one instruction> ; <state>`. The state has
these tokens, as hex numbers without `0x`:
`eax= ecx= edx= ebx= esp= ebp= esi= edi= eip= eflags=`.

The segment registers and their bases are 0. The memory is unlimited, and
every byte that hasn't been written reads as the **memory pattern**:

```
byte(A) = ((A * 2654435761) mod 2^32) >> 24      (A is the 32 bit linear address)
```

The instruction bytes are at linear address `eip` (they replace the pattern
there).

The output is one line for each input line:

```
OK exit=<exit> undef=<eflags bits> eax=XXXXXXXX ecx=... edi=XXXXXXXX eip=XXXXXXXX eflags=XXXXXXXX mem=<writes>
ERR <message>
```

- `exit`:
  - `fall` (no branch);
  - `branch` (any taken branch, call or return);
  - `trap:N` (an interrupt or exception with vector N, such as `trap:0` for a divide error or `trap:3` for int3);
  - `fault:ADDR` (a memory fault, which can't happen with unlimited memory);
  - `undefined` (the instruction isn't lifted);
  - `helper:N` (a helper, which isn't executed).
- `undef`: the EFLAGS bits of the flags the instruction leaves undefined.
- `eflags` is built from the flag registers:
  - CF bit 0, PF 2, AF 4, ZF 6, SF 7, DF 10, OF 11, IF 9, AC 18, ID 21;
  - bit 1 is always set.
- `mem`: the bytes written by the instruction, with their final values. They are sorted by address and merged into runs: `mem=00001000:aabbcc,00002000:11`, or `mem=-` when nothing was written.

The registers are always printed as 32 bits, in 16-bit mode too.

## State v2: segments, x87, SSE

These tokens extend the state. Every token is optional on input, and the
default is given after the `=` below. Every token is always printed on output.

| tokens | value |
|---|---|
| `cs=0 ds=0 es=0 fs=0 gs=0 ss=0` | the selectors |
| `fcw=37f fsw=0 ftw=0` | the x87 control word, the status word (with TOP and C0-C3), and the *abridged* tag word (8 bits, bit i set = physical register i is valid) |
| `r0=0` ... `r7=0` | the physical x87 registers, 20 hex digits (80 bits) |
| `mxcsr=1f80` | |
| `xmm0=0` ... `xmm7=0` | 32 hex digits |
| `mem=ADDR:HEX,...` | input only: bytes written over the memory pattern before the run (used to place valid far pointers and descriptors where the instruction reads them) |

The output also has `fundef=<fsw bits>`, the x87 status bits (C0-C3) that the
instruction leaves undefined (`OpcodeClassification::getFloatStatusUndefined()`, from
`SemanticTemplate::m_floatStatusUndefined`). They are masked like `undef`.

Every output token is printed: `es cs ss ds fs gs` (4 digits), `es_base ... gs_base`
(the base registers of the IR, 8 digits), `fcw fsw ftw`, `r0..r7`, `mxcsr`,
`xmm0..xmm7`. Unicorn doesn't expose the bases of ds/es/ss/cs, so the driver checks
the IR's bases against the selector Unicorn ends with (selector * 16 in real mode,
the fixed GDT in protected mode, 0 for a null selector).

**The comparison** covers the integer registers, eip, eflags, the selectors, the
bases, fcw, fsw (without `fundef`), ftw, mxcsr, xmm0-7, the memory, and r0-r7 for the
registers that are not empty in both results (the value of an empty register is not
defined).

**Segments.** In real mode (16 bit) a segment base is selector * 16. In
protected mode (32 bit):
- A selector of 0 in the *initial* state means the flat descriptor that Unicorn starts with: base 0, limit 4G, usable.
- Any other initial selector is loaded from the fixed GDT below.
- The code bytes are at linear address `cs_base + eip`.
- The CLI lifts with `SEGMENTS_FULL`, so every memory operand adds its segment base.
- Segment limits and access rights are not checked on memory accesses. QEMU doesn't check them either.

The fixed GDT, at linear `0x000f0000`, has `gdtr limit = 0x4f`. LDTR is 0.

| selector | descriptor |
|---|---|
| 0x00 | null |
| 0x08 | code 32-bit, DPL 0, base 0, limit 4G, execute/read |
| 0x10 | data, DPL 0, base 0, limit 4G, read/write |
| 0x18 | data, DPL 0, base 0x10000000, limit 4G, read/write, accessed bit set (the others have it clear, a segment load sets it) |
| 0x20 | code 32-bit, DPL 0, base 0x00002000, limit 4G, execute/read |
| 0x28 | code 16-bit, DPL 0, base 0, limit 0xffff (a far branch to it changes the mode: not lifted) |
| 0x30 | data, DPL 0, base 0, read-only (loading ss with it is #GP) |
| 0x38 | data, DPL 0, base 0, **not present** (#NP, or #SS for ss) |
| 0x40 | data, DPL 3, base 0x20000000, read/write |
| 0x48 | a 32-bit call gate to 0x08:0x3000 (not lifted) |

The states use cs=0x08 (or 0 for the flat start), ss=0x10, and ds/es/fs/gs drawn from {0, 0x10, 0x18, 0x40}. In about half of the states, the lines that load a selector get valid selectors in their register operand, or valid far pointers (`mem=`) at the address they read.

**x87.**
- **Register values** are drawn from ±0, ±1, ±inf, quiet and signaling NaNs, denormals, the largest and smallest normals, pseudo-denormals and unnormals (invalid encodings), and random normals.
- **TOP** is random. **Tags**: Unicorn has no stack faults, so for Unicorn the stack is well formed for the line: `states_v2.x87_needs()` gives the number of valid registers the line needs at the top (the highest ST(i) it names plus one, two for fscale / fprem / fcompp..., at most 7 for a push) and the tags are those of a stack of a random depth in that range. The stack faults are in `x87_edge.asm`, and in the host runs 30% of the states have a random tag word.
- **fcw** is 0x037f in half of the states. In the others the precision (bits 8-9) and rounding (bits 10-11) are random, and the exceptions stay masked.
- **fsw** has random C0-C3 and ES=0.
- **Memory operands**: in 75% of the states the value at the effective address is an edge value of its type (a float edge for m32fp / m64fp, an x87 edge for m80fp, an integer edge for m16int.., a packed BCD number for fbld, a plain control word for fldcw / the images).
- **Unicorn workarounds** (`states_v2.qemu_workarounds()`; none of them with `--host-x87`): the register values keep away from the classes on which Unicorn's x87 is wrong (pseudo-denormals, the unsupported encodings for fxam / fscale / fxtract, NaNs / infinities / denormals for fxtract, values out of range for fbstp / fisttp, tiny results with a reduced precision control, signaling NaNs converted by fst / fld m32 / m64, rounding control for the constants, precision control for fscale). Each is documented in `oracle_bugs.txt` and covered by `x87_edge.asm`.

**SSE.**
- **xmm lanes** are random 32-bit and 64-bit values drawn from the float edge values, plus random integers.
- **mxcsr** is 0x1f80 in half of the states. In the others the rounding, FZ and DAZ are random, and the exceptions stay masked.
- **MMX.** The x87 state is random too (the lines with an `mm` operand), so the TOP, the tags and the exponents of the registers
  after every MMX instruction are compared.
- **Alignment.** Most states of an instruction with an aligned 128 bit operand get an aligned address (the base register is moved,
  `oracle.align_memory_operand`), the others keep the random one and test the #GP.
- **Two NaNs.** The register forms of add, sub, mul and div never get a NaN in both operands of a lane
  (`states_v2.avoid_two_nans`, see oracle_bugs.txt); `sse_edge.asm` has them.
- **`@state:` comments.** A corpus line can carry `; @state: xmm1=... mxcsr=...` (hex tokens of the `run` protocol, any number of
  them). Each is applied on top of a random state and added to the 16 random states of the line.

The SSE results are compared like the rest, with these exceptions (`oracle_bugs.txt` has the evidence of each):
- The exception flags of MXCSR (bits 0-5) are not compared with Unicorn, which never writes them.
- QEMU 5 ignores FZ, returns the original denormal of minps/maxps under DAZ, doesn't raise #GP for a misaligned 128 bit operand
  or for the reserved bits of ldmxcsr, and doesn't set the exponent of an MMX register: `oracle.py` applies the SDM to its result.
- `rcpps`, `rsqrtps` (and the scalar forms) are helpers (the estimate tables of Intel aren't public): UNLIFTED.

**The Rosetta oracle.** `run_semantics.py --rosetta` builds `rosetta_probe.c` (an x86-64 program: `clang -arch x86_64`, it runs under
Rosetta 2 on Apple Silicon) and executes the register-only xmm / general register SSE lines on the host's x86 floating point unit
instead of Unicorn. It reports what QEMU 5 can't: the MXCSR exception flags, FZ, DAZ and the NaN rules, and compares them. The other
lines (memory operands, mm registers, everything that isn't SSE) are ORACLE_ERR. The differences that remain are the ordered /
unordered compares (Rosetta raises DE for a NaN and a denormal, oracle_bugs.txt). Use it after a change of SemanticFloat or of
the float lifters: `--rosetta --file sse.asm,sse2.asm,sse_edge.asm`.

## The oracle (State v2)

- **Segments, 32-bit:** the GDT is written at 0xf0000 and loaded with `UC_X86_REG_GDTR`, then every
  non-zero initial selector is written with `reg_write`, which loads (and checks) the descriptor
  through the GDT. The accessed bits that the loads set are then undone (the GDT bytes are
  written again). A selector of 0 keeps Unicorn's flat start. **16-bit:** `reg_write` of a
  segment register sets base = selector * 16, and `emu_start()` takes the *linear* start
  address (it computes ip = begin - cs * 16), so the code is at cs * 16 + eip and `begin` is that.
- **x87:** `UC_X86_REG_FP0..FP7` are the *physical* registers (80 bit values are
  `(mantissa, sign:exponent)` tuples; `ST0..ST7` are `(TOP + i) & 7` and return only the
  mantissa). `FPSW` carries TOP (bits 11-13) and C0-C3. `FPTAG` is the *full* two-bit tag word
  (3 = empty): a write only keeps "empty or not" (the rest is computed from the register
  values), so the abridged tag word of the protocol is converted both ways
  (`bit i set = tag i != 3`). The initial `FPCW`, `MXCSR` read as 0 and are always written.
- **SSE:** works without setting CR4. `XMM0..7` are 128 bit integers.
- **Accessed bit:** QEMU's far jmp / call / retf leave the accessed bit of the code segment
  descriptor clear, the SDM sets it. `oracle.py` reports the write after a successful far transfer
  (`is_far_transfer`), see oracle_bugs.txt.
- **retf / iret with a null ss:** Unicorn raises #GP for them when ss is the null selector of its
  flat start (push, pop and ret are fine), so the states of these lines in protected mode have ss = 0x10.
- **Real mode stack wrap:** the second access of retf / iret / call far at sp near 0xffff
  doesn't wrap in Unicorn, so the states of these lines keep sp away from the 64K border.

## The State v2 draws (states_v2.py)

The extra state has its own random generator (seeded from the line text), so the integer
registers of the states don't change. All the draws are as in "State v2"; in short:
- Segments: only the lines of the `segments*.asm` files (or `--varied-all`) get non default
  selectors: 32-bit cs in {0, 0x08}, ss 0x10, ds/es/fs/gs in {0, 0x10, 0x18, 0x40}; 16-bit cs in
  {0, 0x100}, others from a list of selectors.
- x87 and SSE: the lines with an `f...` mnemonic or a `xmm` / `mm` operand (or `--fp-state`)
  get random fcw / fsw / ftw / r0-r7 / mxcsr / xmm0-7 from the edge pools.
- Selector operands: in about half of the states the lines that load a selector get a valid
  one: `mov sreg, reg` in the register, `mov sreg, [0x...]`, `lds`..`lgs reg, [0x...]`,
  `jmp / call far [0x...]` at the absolute address (the segment base is added), `pop sreg`,
  `retf` and `iret` on the stack (a frame with a code selector, eflags without VM). Only the
  absolute addresses are known to the harness, so the lines through `[esi]` always fault,
  which tests the faults only.
- A far branch or return to a 16-bit code segment (0x28), through the call gate (0x48), to an
  outer privilege level or to virtual 8086 mode is OP_UNDEFINED: the corpus has a line for
  0x28 and 0x48 (UNLIFTED), the draws avoid them.

## The oracle

Unicorn runs in `UC_MODE_16` (real mode) or `UC_MODE_32`, from the same state:

- **Memory:** pages are mapped on demand and filled with the memory pattern. The code is written at `eip`, and the writes are recorded through a memory hook.
- **Repeated instructions:** a `rep` instruction is stepped until `eip` leaves it, because Unicorn may stop after one iteration.
- **Traps:** interrupts and exceptions stop the run through the interrupt hook, and the result is reported as `trap:N`.
- **Comparing a trap:** when the exit is a trap, `eip` is not compared, because the two engines report it at different points.

## States

For each line, `--states N` random states (16 by default) are drawn, seeded
from the line text so that each run is reproducible.

- **Register values** are drawn from the edge values (0, 1, 0x7f, 0x80, 0xff, 0x7fff, 0x8000, 0xffff, 0x7fffffff, 0x80000000, 0xffffffff) and from random values.
- **ecx** is small (0 to 17) in half of the states, and in every state of a `rep`/`loop` line.
- **eflags** is 0x202 plus random CF, PF, AF, ZF, SF, OF and DF.
- **eip** is 0x1000.

## Report

`out/semantics/report.json`, `summary.md` and `failures.txt`. Each line gets one status:

| status | meaning |
|---|---|
| PASS | every state matched |
| FAIL | a state differs (the first differences are in failures.txt, with the state, so they can be replayed with `--grep` and `-v`) |
| UNLIFTED | dismount exits `undefined` / `helper` |
| SKIP | matched by skip.txt |
| ORACLE_BUG | failed, and matched by oracle_bugs.txt: a documented Unicorn/QEMU bug where dismount follows the SDM (a line that starts to pass becomes PASS) |
| ASM_ERR / DIS_ERR / ORACLE_ERR | nasm, dismount_cli or Unicorn failed on the line |

The driver exits 0 even when lines fail. With `--strict` it exits 1 on any FAIL
or DIS_ERR. `--baseline OLD.json` prints the lines that passed in OLD and don't
pass now, and exits 1 if there are any.

## Phases

1. Integer core:
   - data movement, arithmetic, logic, shifts and rotates, multiply and divide, bits;
   - flags, setcc/cmovcc/jcc, the stack, call/ret/jmp, loop/jcxz;
   - string instructions and rep, xchg/xadd/cmpxchg/cmpxchg8b with and without lock;
   - cbw/cwd, bswap, enter/leave, pushf/popf/lahf/sahf, int/int3/into.
2. Segments: segment register loads, lds/les/lfs/lgs/lss, far jmp/call/retf,
   iret (real mode, and protected mode without privilege change).
3. x87 (see below).
4. MMX, SSE and SSE2 (decoding them is part of the work).

## x87

`IA32SemanticTableX87.cpp` lifts every x87 instruction of the decoder, fxsave and fxrstor: see the
comment at its top for the model (the stack, the tags, the stack faults, ES / B, the faults and
the traps, C1, #MF). The fsin, fcos, fsincos, fptan, fpatan, f2xm1, fyl2x and fyl2xp1 are
`OP_HELPER` (their results depend on the processor): UNLIFTED in the comparison. What is not kept:
the instruction and data pointers and the opcode (FIP, FDP, FOP: the images store zeros), the exponent
scaling of an unmasked overflow or underflow (the masked response is stored).

### Directed states: `corpus/x87_edge.asm`

Lines of the form `instruction ; @x87: tokens` run from exactly that state (4 states, the integer
registers random), see `x87states.py` for the tokens. `tag=` names the group of a case, the regexes of
`oracle_bugs.txt` use it (`;; ...` in a regex is the annotation: the text a regex sees is
`instruction ;; tokens`). The file is generated: `python3 tests/semantics/tools/gen_x87_edge.py`.

### Unicorn's x87

QEMU 5.0 has many x87 inaccuracies: no stack faults (it reads an empty register as a number), no
unmasked exceptions, the exception flags are not copied from the soft float status (only ZE of fdiv,
wrongly), C1 is never written, the rounding control is ignored by the constants, and a long list of
special cases (pseudo-denormals, unsupported encodings in fxam / fxtract, fisttp / fbstp overflow, the
sign of fbstp, signaling NaNs...). `oracle_bugs.txt` lists them with their evidence: the status bits
that are always wrong are masked per line (`@fsw-mask=`), the others make the line ORACLE_BUG. The
values the harness leaves out of the random states are listed in `states_v2.qemu_workarounds()`.

### The host x87 oracle

`run_semantics.py --host-x87` runs the x87 lines on the x87 unit of the machine instead of Unicorn:
`tools/x87_host.c` (built on the first use with the system compiler, `clang -arch x86_64` on an
Apple silicon Mac, where it runs under Rosetta 2) executes the instruction, with its memory operand
rewritten to [rdi], from the state loaded by `fxrstor`, and dumps the state with `fxsave`. It models the
stack faults, the C1 and the exception flags, and it agrees with dismount on the corpus: `x87.asm` and
`x87_edge.asm` pass (UNLIFTED excepted). Rosetta 2 is a software x87: `host_x87_quirks.txt` has
what it gets wrong (the loads don't clear C1, a denormal m32fp / m64fp operand doesn't raise DE, fbld
doesn't detect the stack overflow, a NaN operand wins over a stack fault, the unmasked exceptions are not
implemented, fldenv / frstor / fldcw / fxrstor don't derive ES, fxrstor doesn't #GP a reserved MXCSR bit,
no ffreep / fsetpm) and `x87host.py` the rest (the tag word of fnstenv and fnsave is computed from the
registers, the FXSAVE padding). On a real x86 processor the same helper runs natively.

```
out/venv/bin/python tests/semantics/run_semantics.py --host-x87 --file x87.asm,x87_edge.asm
out/venv/bin/python tests/semantics/tools/check_x87_unmasked.py   # the unmasked exceptions and #MF, by the SDM
```
