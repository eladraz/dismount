# ARM test plan

dismount's ARM support (A32, T32, A64 with Advanced SIMD, SVE, SVE2, SME and
SME2) is checked against LLVM for the encodings and against a reference
processor for the semantics. The headers are `Include/dismount/proc/arm/*`
and `Include/dismount/assembler/proc/arm/ArmAssembler.h`; read them first.

## Oracles

| What | Oracle | Notes |
|---|---|---|
| Decoding and text | `objdump -d` (Apple LLVM 21) over `.inst` words | A64 decodes every extension by default. For AArch32 pass the `--mattr` of the features. `<unknown>` means invalid |
| Assembling | `clang -c` (integrated assembler) with `-target aarch64-none-elf -march=armv9.4-a+...` / `-target armv8a-none-eabi -mfpu=...`, `.arm` / `.thumb` / `.syntax unified` | The error `instruction requires: <feature>` names the feature an instruction needs, and checks the feature marks |
| A64 semantics | Unicorn 2.1.4 (`UC_ARCH_ARM64`, cpu max: NEON, SVE with VL 128) and the host (Apple M4: A64, NEON, FP16, dotprod, i8mm, bf16, SME / SME2 in the streaming mode with SVL 512) | The host runner is a C program with a `MAP_JIT` page (like `tests/semantics/rosetta_probe.c`) |
| A32 / T32 semantics | Unicorn (`UC_ARCH_ARM`, `UC_MODE_ARM` / `UC_MODE_THUMB`, a cortex-a15 / max cpu with NEON and VFPv4) | The host has no AArch32 |

The venv is `out/venv` (`unicorn==2.1.4`).

## dismount_cli

The line protocol of `tests/ia32/dismount_cli.cpp` takes `--arch a32|t32|a64`
(instead of `--bits`) and `--mattr <llvm feature list>` (default: all
features):

- `dismount_cli dis --arch a64` reads hex words, one instruction per line, and
  prints `OK <size> <text>` or `INVALID <size>`. For T32 the input is the hex
  of the halfwords as objdump prints them (`eb01 0002` or `eb010002`, and
  `1888` for 16 bits). An `@<address>` prefix gives the address of the
  instruction, for the branch targets.
- `dismount_cli asm --arch a64` reads one instruction per line and prints
  `OK <hex>` or `ERR <message>`. T32 tracks the it blocks over the lines.
- `dismount_cli run --arch a64` runs the lifted IR over a state, as the
  IA-32 protocol does (see `tests/semantics/TEST_PLAN.md`), with the ARM
  registers.
- `dismount_cli features --arch a64` prints the support matrix
  (`ArmFeatures::getSupport()`).

## The encoding tests (`tests/arm/run_compat.py`)

1. The corpus `tests/arm/corpus/<a32|t32|a64>/<feature>.s` holds instruction
   lines, each tagged `// @feature: <llvm name>` when it isn't base. It is
   generated by `tests/arm/tools/gen_corpus.py` from two sources:
   - every encoding of the dismount tables, instantiated with several
     operand values (all the registers classes, the boundary immediates,
     each addressing form), and
   - a frozen sample of random words which objdump decodes (seeded, so the
     corpus finds what dismount doesn't implement). The feature of a line is
     what clang asks for.
2. Each line is assembled by clang and by dismount (ASM column), and the
   bytes of clang are disassembled by objdump and by dismount (DIS column,
   the text is compared after normalizing the whitespace and the comments).
   The dismount text is assembled again by dismount (RT, the round trip).
3. `--strict` exits 1 on any failure, `compare_reports.py` (shared with
   tests/ia32) reports the regressions against an older report.

## The fuzzers

- `tests/arm/tools/fuzz_decode.py --arch a64 --count N --seed S`: random
  words (and random words inside the encoding classes, so the sparse
  spaces are reached) through objdump and dismount. A bug is: a different
  text, dismount decodes and objdump says `<unknown>` (or the reverse, for
  the features dismount marks SUPPORT_DISASSEMBLE), or a crash.
- `tests/arm/tools/fuzz_roundtrip.py --arch a64`: every word dismount
  decodes is formatted, assembled by dismount and must give the same word
  (or a word with the same text, for ARM_ENTRY_DECODE_ONLY).

## The semantics tests (`tests/arm/semantics/run_semantics.py`)

The same design as `tests/semantics`: each corpus line runs from random and
directed states in dismount (`run`) and in the oracles, the registers,
flags, memory and floating point status are compared, and
`oracle_bugs.txt` / `skip.txt` document the oracle mistakes with evidence.
`--arch`, `--oracle unicorn|host`, `--strict`, `--baseline` as in
tests/semantics.

## The support matrix

`ArmFeatures::getSupport()` marks each feature with what dismount does
(disassemble, assemble, lift, partial lift) and what is verified.
`tests/arm/tools/gen_support_matrix.py` writes `tests/arm/SUPPORT.md` from
`dismount_cli features` and the latest reports (the counts of lines per
feature that pass), and checks that a feature marked SUPPORT_LIFT has no
UNLIFTED line in the semantics report. Update the marks with each change.
