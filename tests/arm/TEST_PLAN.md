# ARM test plan

dismount's ARM support (A32, T32, A64 with Advanced SIMD, SVE, SVE2, SME and
SME2) is checked against LLVM for the encodings and against a reference
processor for the semantics. The headers are `Include/dismount/proc/arm/*`
and `Include/dismount/assembler/proc/arm/ArmAssembler.h`; read them first.

## Oracles

| What | Oracle | Notes |
|---|---|---|
| Decoding and text | `objdump -d` (Apple LLVM 21) over `.inst` words | A64 decodes every extension by default. For AArch32 pass the `--mattr` of the features. `<unknown>` means invalid |
| Assembling | `clang -c` (integrated assembler) with `-target aarch64-none-elf -march=armv9.4-a+...` / `-target armv8a-none-eabi -mfpu=...`, `.arm` / `.thumb` / `.syntax unified` | The error `instruction requires: <feature>` names the feature an instruction needs, and checks the feature marks |
| A64 semantics | Unicorn 2.1.4 (`UC_ARCH_ARM64`, cpu max: NEON, SVE with VL 128) and the host (Apple M4: A64, NEON, FP16, dotprod, i8mm, bf16, SME / SME2 in the streaming mode with SVL 512) | The host runner is a C program with a `MAP_JIT` page (like `tests/semantics/rosetta_probe.c`) |
| A32 / T32 semantics | Unicorn (`UC_ARCH_ARM`, `UC_MODE_ARM` / `UC_MODE_THUMB`, a cortex-a15 / max cpu with NEON and VFPv4) | The host has no AArch32 |

The venv is `out/venv` (`unicorn==2.1.4`).

## dismount_cli

The line protocol of `tests/ia32/dismount_cli.cpp` takes `--arch a32|t32|a64`
(instead of `--bits`) and `--mattr <llvm feature list>` (default: all
features):

- `dismount_cli dis --arch a64` reads hex words, one instruction per line, and
  prints `OK <size> <text>` or `INVALID <size>`. For T32 the input is the hex
  of the halfwords as objdump prints them (`eb01 0002` or `eb010002`, and
  `1888` for 16 bits). An `@<address>` prefix gives the address of the
  instruction, for the branch targets.
- `dismount_cli asm --arch a64` reads one instruction per line and prints
  `OK <hex>` or `ERR <message>`. T32 tracks the it blocks over the lines.
- `dismount_cli run --arch a64` runs the lifted IR over a state, as the
  IA-32 protocol does (see `tests/semantics/TEST_PLAN.md`), with the ARM
  registers.
- `dismount_cli features --arch a64` prints the support matrix
  (`ArmFeatures::getSupport()`).

## AArch32 (A32 and T32)

The tables of A32, T16, T32 and of the floating point / Advanced SIMD
instructions (`ArmEncodingTableA32.cpp`, `...T16.cpp`, `...T32.cpp`,
`...A32Simd.cpp`) are generated by `tests/arm/tools/gen_aarch32_tables.py`
from the instruction records of the LLVM ARM backend (the bits of each
encoding, the operands and the assembly string), dumped with `llvm-tblgen
--dump-json` (`aarch32_llvm.py` says how: `LLVM_SRC` / `LLVM_ARM_JSON`, the
generated C++ is committed and doesn't need LLVM). The operand classes of LLVM
are mapped to the specs of `ArmOperandCodecA32.h` in `aarch32_classes.py`
(`aarch32_classes_thumb.py`, `aarch32_classes_simd.py`), and the places where
the oracle (the LLVM 21 of `objdump`) differs from the records, or where
LLVM's C++ decoder / printer does something the records don't say (the
aliases of `mov` with shifts, `push` / `pop`, the hints, `cps`, `rfe`...), are
patched in `aarch32_a32.py`, `aarch32_thumb.py`, `aarch32_simd.py`. Run
`python3 tests/arm/tools/gen_aarch32_tables.py` after a change.

The oracle needs the features of AArch32 explicitly (`armlib.OBJDUMP_MATTR`),
the same list is dismount's default (`ArmFeatureSet::all()`). The entries
which exist before ARMv8 only (`ARM_ENTRY_PRE_V8`: swp, mcr2...) are checked
with `--mattr` lists without `v8` by the directed rows.

Specifics of the AArch32 tests:

- The corpus (`corpus/a32`, `corpus/t32`) is generated by `gen_corpus.py --arch
  a32|t32` (`gen_corpus_aarch32.py`). A line is kept when clang assembles it
  and its bytes disassemble to the same text; the features of a line are the
  smallest set with which dismount decodes it (the lines dismount doesn't
  decode are listed in `out/compat-arm-<arch>/pending.txt`). A T32 unit that
  needs an it block is a line with several instructions separated by `;`
  (`it eq ; addeq r0, r1, r2`).
- `run_compat.py --arch a32|t32|all` as for A64. The branch targets are
  written relative to the line (`bl .+8`).
- `tests/arm/tools/check_features.py --arch a32|t32` compares the features of
  the tables with clang: every corpus line is assembled by clang for the
  triples of the architecture versions (armv4t ... armv8-a, with the
  floating point variants) and by dismount with the same `--mattr armvN`,
  and the two must accept the same lines (the known exceptions are the
  clang quirks listed in the script, and for T32 the operand restrictions of
  the older architectures, the it block checks and the range of bl).
- `fuzz_decode.py` and `fuzz_roundtrip.py` take `--arch a32|t32`. T32 random
  words are 16 or 32 bit units (the first halfword decides, like objdump) and
  never contain an `it`, because the it state of a stream would carry over to
  the following random units; the it blocks are tested by directed units.
- `tests/TestArmAArch32Disassembler.cpp` has the rows
  (`AArch32TestRows_A32.inc`, `..._T32.inc`, `..._Simd.inc`), the features,
  the it blocks and the assembler.

## The encoding tests (`tests/arm/run_compat.py`)

1. The corpus `tests/arm/corpus/<a32|t32|a64>/<feature>.s` holds instruction
   lines, each tagged `// @feature: <llvm name>` when it isn't base. It is
   generated by `tests/arm/tools/gen_corpus.py` from two sources:
   - every encoding of the dismount tables, instantiated with several
     operand values (all the registers classes, the boundary immediates,
     each addressing form), and
   - a frozen sample of random words which objdump decodes (seeded, so the
     corpus finds what dismount doesn't implement). The feature of a line is
     what clang asks for.
   The scalar floating point and Advanced SIMD lines are `simd.s` (ARMv8.0)
   and `simd-<feature>.s`; `gen_corpus.py --class simd` writes only them
   (their instantiations of the table have a random stream of their own, so
   the other files don't change when the SIMD table does). The table
   `Arm64EncodingTableSimd.cpp` is generated by `tools/gen_a64_simd_table.py`
   (groups in `a64groups_fp.py`, `a64groups_simd.py`, `a64groups_crypto.py`,
   `a64groups_simdmem.py`), and the rows of `tests/TestArm64Simd.cpp` by
   `tools/gen_simd_unit_rows.py`.
2. Each line is assembled by clang and by dismount (ASM column), and the
   bytes of clang are disassembled by objdump and by dismount (DIS column,
   the text is compared after normalizing the whitespace and the comments).
   The dismount text is assembled again by dismount (RT, the round trip).
3. `--strict` exits 1 on any failure, `compare_reports.py` (shared with
   tests/ia32) reports the regressions against an older report.

## The fuzzers

- `tests/arm/tools/fuzz_decode.py --arch a64 --count N --seed S`: random
  words (and random words inside the encoding classes, so the sparse
  spaces are reached) through objdump and dismount. A bug is: a different
  text, dismount decodes and objdump says `<unknown>` (or the reverse, for
  the features dismount marks SUPPORT_DISASSEMBLE), or a crash. The
  scalar floating point and Advanced SIMD class is compared like the base
  one; `--class simd` restricts the words to that sparse class and `--tops
  0e,4e` to the given top bytes. `check_range.py --top` compares whole top
  bytes (every Nth word).
- `tests/arm/tools/fuzz_roundtrip.py --arch a64`: every word dismount
  decodes is formatted, assembled by dismount and must give the same word
  (or a word with the same text, for ARM_ENTRY_DECODE_ONLY, and for the
  fields which LLVM ignores). `--class simd` as for fuzz_decode.py.

## The semantics tests (`tests/arm/semantics/run_semantics.py`)

The same design as `tests/semantics`: each corpus line runs from random and
directed states in dismount (`run`) and in the oracles, the registers,
flags, memory and floating point status are compared, and
`oracle_bugs.txt` / `skip.txt` document the oracle mistakes with evidence.
`--arch`, `--oracle unicorn|host`, `--strict`, `--baseline` as in
tests/semantics.

## The support matrix

`ArmFeatures::getSupport()` marks each feature with what dismount does
(disassemble, assemble, lift, partial lift) and what is verified.
`tests/arm/tools/gen_support_matrix.py` writes `tests/arm/SUPPORT.md` from
`dismount_cli features` and the latest reports (the counts of lines per
feature that pass), and checks that a feature marked SUPPORT_LIFT has no
UNLIFTED line in the semantics report. Update the marks with each change.

## Gates of a change

- `out/bin/test_dismount` passes (tests/TestArm*.cpp).
- `run_compat.py --arch all --strict` exits 0, with no regression.
- `fuzz_decode.py` and `fuzz_roundtrip.py` are clean for every
  instruction set (seeds 1 and 7, 200000 words).
- `run_semantics.py --strict` for every instruction set and oracle, no
  regression.
- The IA-32 gates (tests/ia32/TEST_PLAN.md, tests/semantics/TEST_PLAN.md)
  still pass.
