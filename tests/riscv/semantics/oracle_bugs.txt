# Lines where an oracle is wrong (or is a different processor) and dismount follows the RISC-V specification,
# as `[arch,oracle,file,...] <regex>  # <reason>`. The lines are still run: a failing line that matches is
# ORACLE_BUG instead of FAIL, a passing one is PASS. In a --cross run a rule applies when it names one of
# the two oracles. Each entry needs the evidence, so it can be re-checked when an oracle is upgraded
# (Unicorn 2.1.4 = QEMU 5.0.1, QEMU 11.1.3, Spike 1.1.1-dev commit 2ca5489).
#
# The evidence is the directed lines of corpus/rv_oracle_diffs.s:
#     run_semantics.py --cross qemu,unicorn --file rv_oracle_diffs --states 1 -v
#     run_semantics.py --cross qemu,spike   --file rv_oracle_diffs --states 1 -v
#     run_semantics.py --cross unicorn,spike --file rv_oracle_diffs --states 1 -v
# QEMU 11 and Spike agree on every scalar line of the starter corpus and on the vector sample but the
# lines below; Unicorn differs from both on the lines below (the third column of the evidence).

# --- Unicorn bugs and missing features (QEMU 5.0.1, the cpu model "any")

# fmin / fmax with a signaling NaN and a number return the canonical NaN; the specification (F 2.2, "If only
# one operand is a NaN, the result is the non-NaN operand", and the invalid flag for the signaling NaN) and
# QEMU 11 / Spike return the number. A quiet NaN and a number agree. Evidence: rv_oracle_diffs line 8,
# fmax.s with f11 = ffffffff7f800001 (sNaN), f12 = 1.0: QEMU / Spike f10 = 3f800000, Unicorn 7fc00000.
[unicorn] ^f(min|max)\.[sd] # Unicorn: fmin / fmax of a signaling NaN and a number return the canonical NaN instead of the number

# Single precision values are not NaN boxed: a result is written zero extended (the upper 32 bits are 0, not
# ones) and an operand which is not boxed is used as is (the specification reads it as the canonical NaN).
# Evidence: rv_oracle_diffs lines 18-20 (fadd.s / fsgnj.s / fcvt.d.s of f11 = 000000003f800000: QEMU / Spike
# give the canonical NaN result, Unicorn adds 1.0 + 2.0). The cross-check draws properly boxed inputs and
# compares the low 32 bits of the single results only (run_semantics.py, f_single_result()).
[unicorn,rv_oracle_diffs] ^(fadd|fsgnj|fcvt\.d)\.s # Unicorn: no NaN boxing

# Atomics at a misaligned address always trap (address misaligned, mcause 6 in QEMU 5); RVA23 requires Zama16b:
# a misaligned AMO / lr / sc inside an aligned 16 byte region completes. Evidence: rv_oracle_diffs lines 23-26
# (win+1001, win+1003 and win+1004 for the word AMOs: QEMU / Spike fall through, Unicorn trap:fault).
[unicorn,rv_oracle_diffs] ^(amo|lr\.|sc\.) # Unicorn: no Zama16b (misaligned atomics inside a 16 byte region trap)

# An sc.w / sc.d which fails (no reservation) to an address which isn't mapped does not take the access fault;
# QEMU 11 and Spike take it (the address is translated before the reservation is checked). Evidence:
# rv_oracle_diffs line 29, sc.w a0, a2, (a1) with a1 = window + 0x8000: QEMU / Spike trap:fault, Unicorn fall.
[unicorn,rv_oracle_diffs] ^sc\.[wd] # Unicorn: a failing sc doesn't fault on an unmapped address
[unicorn] ^sc\.[wd] # Unicorn: a failing sc doesn't fault on an unmapped address (random states point outside of the window now and then)

# --- QEMU 11.1.3 deviations (Spike is the verdict)

# AMOs at a misaligned address which crosses a 16 byte aligned granule complete in QEMU (the access is split);
# with Zama16b the instruction may complete only when the access is inside one aligned 16 byte region, else
# it raises the address-misaligned or access-fault exception (A extension). Spike raises the access fault
# (mcause 7). Evidence: rv_oracle_diffs line 24 (amoadd.w at window + 0x100d; QEMU fall, Spike trap:fault,
# also amoadd.d at window + 0x1009, amoadd.w at + 0x100e / 0x100f).
[qemu,rv_oracle_diffs] ^amo # QEMU: a misaligned AMO crossing a 16 byte granule completes (Spike raises the access fault)
# The same, in the directed lines (rv_dir_atomic / rv64_dir_atomic: the AMOs at win + 0x100..0x10f and the
# page edges). The rule only turns a failing line into ORACLE_BUG: the lines whose states don't cross a
# granule pass, and the Spike runs of the same lines are the verdict (no rule for Spike).
[qemu,rv_dir_atomic,rv64_dir_atomic,rv32_dir_atomic] ^amo(swap|add|xor|and|or|min|max|minu|maxu)\.[wd] # QEMU: a misaligned AMO crossing a 16 byte granule completes (Spike raises the access fault)

# Zabha and Zacas: QEMU raises the access fault for a misaligned amo*.b/.h and amocas.* even inside a 16 byte
# region, as if Zama16b didn't apply to them; Zama16b is for loads, stores and AMOs, and the AMOs of Zabha
# and Zacas are AMOs: a misaligned access inside the granule completes (Spike, and dismount). Evidence:
# run_semantics.py --cross qemu,spike --file rv_dir_atomic: amoadd.h a0, a2, (a1) at win + 0x101: QEMU
# trap:fault, Spike fall (also amocas.h and amocas.w / amocas.d at win + 0x104..0x10c).
[qemu,rv_dir_atomic,rv64_dir_atomic,rv32_dir_atomic] ^amo\w+\.h|^amocas # QEMU: a misaligned amo*.h or amocas inside a 16 byte region faults (Spike completes it, as Zama16b says)

# lr / sc: what invalidates a reservation is the implementation's choice beyond the aligned address of the
# pair. dismount keeps the reservation until an sc (of the size of the lr and the address of the lr) or a
# new lr; QEMU makes the sc fail when a store of the same hart changed the value in between (it implements
# sc as a compare and swap with the value the lr loaded), Spike makes an sc of the other size (lr.w; sc.d
# or lr.d; sc.w) at the same address succeed. The specification allows both. Evidence: run_semantics.py
# --cross qemu,spike --file rv64_dir_atomic: lr.w a0, (a1) ; sc.d a3, a2, (a1): x13 = 1 on QEMU, 0 on
# Spike; lr.d a0, (a1) ; sw a2, 0(a1) ; sc.d a3, a2, (a1): the same.
[qemu,rv_dir_atomic,rv64_dir_atomic] ^lr\.[wd] .*; (sw|amo\w+\.[wd]) .*; sc # QEMU: an sc fails after a store or an AMO of the same hart changed the loaded value (dismount, like Spike, keeps the reservation)
[qemu,spike,rv_dir_atomic,rv64_dir_atomic] ^lr\.w .*; sc\.d|^lr\.d .*; sc\.w # QEMU and Spike: an sc of the other size than the lr is decided by the value (QEMU: the compare and swap of the sc against the loaded value) or succeeds (Spike); dismount makes it fail

# vsetvli / vsetvl with rd = rs1 = x0 keeps vl: when the new vtype changes VLMAX the behavior is "reserved" in
# the specification: QEMU (rvv_vsetvl_x0_vill=true) sets vill only when the kept vl doesn't fit the new VLMAX,
# Spike sets vill whenever the SEW/LMUL ratio changes. Evidence: run_semantics.py --cross qemu,spike --file rv_v
# (vsetvli zero, zero, e32, m1 from e64, m4 with vl = 4: QEMU vl = 4 vtype = d0, Spike vl = 0 vtype = vill).
[qemu,spike] ^vsetvli? zero, zero # reserved behavior: QEMU keeps vl when it fits the new VLMAX, Spike sets vill when the ratio changes

# --- Spike

# Spike raises the illegal instruction exception for a vector arithmetic instruction with vstart != 0 (the
# specification permits it: "implementations are permitted to raise an illegal-instruction exception when
# executing a vector instruction with a nonzero vstart" for the instructions that can't be interrupted); QEMU
# runs them from vstart. The oracle drops those states (oracle_spike.py: ORACLE_ERR for the state).

# vfwmaccbf16.vf (Zvfbfwma) does not check the NaN boxing of its scalar bf16 operand: a value whose upper 48
# bits are not all ones must read as the canonical NaN (the NaN boxing check of the scalar operand of the .vf
# instructions when SEW < FLEN); QEMU uses the low 16 bits. Spike checks it, and QEMU checks it for the Zvfh
# instructions (vfadd.vf with SEW = 16 passes). Evidence: rv_oracle_diffs lines 38-40: f11 = ffffffff40000000
# (bits 16..31 are not ones) gives +inf with the overflow flag in QEMU, the canonical NaN lanes in Spike.
[qemu] ^vfwmaccbf16\.vf # QEMU: no NaN boxing check of the scalar operand of vfwmaccbf16.vf (Spike is right)

# QEMU 11 RV32: a write of mstatush.MPELP is ignored (the machine mode can't start a U-mode program with ELP
# set); the reads work (a jalr sets ELP, the trap stores it in MPELP). The RV32 states with elp = 1 are
# ORACLE_ERR on QEMU (oracle_qemu.py), Spike runs them. Evidence: a guest `lpad 1` with mstatush = 0x200 falls
# through on QEMU and raises the software check exception (mcause 18, mtval 2) on Spike.

# QEMU 11.1.3 aborts (assertion failed in target/riscv/tcg/vector_helper.c:395 vext_page_ldst_us, rc = -6) on a
# whole register load or store (vl1re8.v .. vl8re64.v, vs1r.v .. vs8r.v) whose vstart is not below the number of
# elements; the specification makes it a no-op (vstart >= the number of elements: nothing is transferred). The
# oracle splits a batch which dies down to the test that kills it and that state is ORACLE_ERR. Evidence:
# run_semantics.py --oracle qemu --oracle-only --file rv_v --states 300 (vl2re16.v v8, (a1): 7 states).

# --- Implementation-defined behavior where the specification allows both (dismount follows QEMU)

# A misaligned store that faults on its last bytes: Spike emulates the access byte by byte and the bytes below
# the faulting one are written; QEMU checks the whole access first and writes nothing, as dismount does. The
# specification leaves the partial effects of a misaligned access that traps to the implementation ("the access
# may be implemented as a sequence of byte accesses"). Evidence: run_semantics.py --oracle spike --file
# rv_gen_base --grep '^sw a2, -3\(a1\)': sw at window + 0x3ffd: Spike writes the byte at 0x3ffd, QEMU doesn't.
[spike] ^(sb|sh|sw|sd|fsh|fsw|fsd)\b # Spike: a store that faults on its upper bytes writes the lower ones (implementation defined)

# The ssp CSR of Zicfiss has no WARL field in the specification (it is URW: any value is read back, the
# shadow stack accesses are what must be aligned), and QEMU keeps all the bits. Spike clears the bits below
# XLEN / 8. Evidence: run_semantics.py --cross qemu,spike --file rv_gen_zicsr --grep 'ssp': csrw ssp, a1 with
# a1 = 0xf422933: QEMU ssp = 0xf422933, Spike 0xf422930.
[spike] \bssp\b # Spike: the ssp CSR drops the low bits (QEMU and the specification keep them)

# --- Unicorn (QEMU 5.0.1) on the generated scalar corpus (evidence: run_semantics.py --oracle unicorn --file rv_gen_base,rv_gen_f,rv_gen_d,rv_gen_zicsr,...)
[unicorn] ^(sb|sh|sw|sd|fsh|fsw|fsd)\b # Unicorn: a store that faults on its upper bytes writes the lower ones (implementation defined, see Spike)
[unicorn] \b(vstart|vxsat|vxrm|vcsr|vl|vtype|vlenb)\b # Unicorn has no V extension: its CSRs are illegal
[unicorn] ^li\b # the li of 2048 is a bseti (Zbs): illegal in Unicorn
[unicorn] ^f(n?m)(add|sub)\.[sd] # Unicorn (softfloat of QEMU 5): fused multiply-add with infinity * 0 and a quiet NaN addend doesn't raise invalid; QEMU 11 and Spike do, as F 2.2 requires (fmadd.d with f11 = -inf, f12 = 0, f13 = 7ff8000000000001: Unicorn fflags 0, QEMU 11 / Spike / dismount 0x10)
