# RISC-V test plan

dismount's RISC-V support (RV32 and RV64: the scalar, compressed and privileged
instructions; the vector table and the semantic lifter are separate) is
checked against LLVM 23 for the encodings. The headers are
`Include/dismount/proc/riscv/*` and
`Include/dismount/assembler/proc/riscv/RiscvAssembler.h`; read them first.

## Oracles

| What | Oracle | Notes |
|---|---|---|
| Decoding and text | `llvm-objdump -d --no-print-imm-hex --mattr=...` (`-M no-aliases`, `-M numeric`) over a bare ELF object | The ELF has one `.text` section and no symbols (`rvlib.make_elf`), so every byte is code. `<unknown>` is an invalid unit |
| Assembling | `llvm-mc -triple=riscv64 / riscv32 -mattr=... -filetype=obj`, with `.option norvc` for the 32 bit encodings and without it for the compression | Every line gets a label, so the bytes of each line (and of the multi instruction pseudo instructions) are read from the object (`rvlib.llvm_assemble`) |
| Profiles | `clang --target=riscv64 -march=<profile> -###` | The `-target-feature` list (`tools/check_profiles.py`) |

The tools are looked up in `$RISCV_LLVM_BIN` (default `/opt/homebrew/opt/llvm/bin`):
the system clang and objdump are Apple's and do not know RISC-V. LLVM has no
"+all" for RISC-V: the "all" feature list is `rvlib.all_features()`, built
explicitly (Zcf is left out of RV64, which LLVM rejects). The vector features
are not part of it: the vector table is empty, `tools/fuzz_decode.py` skips
what llvm-objdump decodes as a vector instruction.

## dismount_cli

`tests/ia32/dismount_cli.cpp` takes `--arch rv32|rv64`, `--mattr <list>` (an
LLVM feature list or an ISA string / profile, see `RiscvFeatureSet::parse`;
default: all), `--format no-aliases,numeric` and `--no-rvc`:

- `dis`: each line is `[@<hex address> ]<groups of 4 / 8 hex digits>`, the value of
  each instruction as objdump prints it. Prints `OK <size> <text>`, `INVALID <size>`
  or `ERR <message>`.
- `sweep`: each line is `[@<hex address> ]<raw bytes in memory order>`, a linear
  sweep with the fault tolerance on, as objdump lists a section: `OK <size>:<text>
  ; ...`, `1:<unknown>` for each byte of an invalid unit.
- `asm`: each line is `[@<hex address> ]<statement>` (statements are separated
  by `;`). Prints `OK <hex bytes>` or `ERR <message>`. The compression is on
  unless `--no-rvc`.
- `features` (the support matrix), `entries` (the encodings), `set` (the LLVM
  names of the features of `--mattr`, with their implications).

## The tables

`RiscvEncodingTable*.cpp` and the `.inc` files next to them are generated by
`tools/gen_encoding_tables.py` from the instruction lists of
`tools/riscvinsns.py` (the operand tokens are `tools/riscvdsl.py`): the mask
of an entry is every bit which is not a field of its operands and the value
is what llvm-mc gives for an example (a second example, with other operand
values, is checked to give the same fixed bits). The generator also marks
`RISCV_ENTRY_DECODE_UNGATED` for the entries which llvm-objdump decodes with
no feature (Zicsr, Zifencei, the hint aliases...). The CSR names
(`RiscvCsrNames.cpp`) are generated by `tools/gen_csr_table.py` from
llvm-objdump (LLVM 23 does not gate the names by feature). Run the
generators after a change.

## The checks

`run_compat.py` runs the corpus (`corpus/rv32`, `corpus/rv64`, generated by
`tools/gen_corpus.py`: every instruction of the lists with every register of
each class, the edge values of each immediate and the values just outside of
them, every rounding mode, every fence set, every CSR name, the pseudo
instructions) and checks per line:

| Check | What |
|---|---|
| ASM | llvm-mc without compression and dismount (`--no-rvc`) give the same bytes; a line which LLVM rejects is rejected |
| ASMC | the same with the compression on (the lines which are not `c.*`) |
| DIS, DISNA, DISNUM | the text of llvm-objdump (default, `-M no-aliases`, `-M numeric`) is dismount's |
| RT | dismount's text (default for the 32 bit instructions, no-aliases for all) assembled by dismount gives the bytes (or other bytes with the same text) |
| FEAT | with the features of the line and without the first one, llvm and dismount agree on the text of the bytes and on assembling the line |

`tools/fuzz_decode.py`: random 16 / 32 bit encodings (random, made from a random
entry, and an entry with flipped bits, and the longer formats) in a stream;
dismount and llvm-objdump list the same units for six feature sets (`all`,
`rva23u64`, `rva23s64`, `rv64gc`, `rv32gc`, `rv64i`) in the default and the
no-aliases formats. `tools/fuzz_roundtrip.py`: the texts of the decoded
encodings assembled by dismount and llvm-mc give the bytes, and the
compression of the 32 bit texts is llvm-mc's. `tools/syntax_probe.py`: odd
syntax (the number forms, the case, the blanks, constant expressions, the
fence sets, `;`) accepted or rejected as llvm-mc does.
`tools/check_profiles.py`: the profiles and the implications against clang.

The unit test `tests/TestRiscvDisassembler.cpp` pins the LLVM text with the rows
of `RiscvTestRows.inc` (generated by `tools/gen_unit_rows.py`: a few shapes of every
mnemonic, in the three formats, and the pseudo instruction rows of
`RiscvPseudoRows.inc`) and checks the invalid encodings, the RV32 / RV64
differences, the features, the stream, the operands and the assembler.

## Running

```
cd build && cmake .. -DCMAKE_BUILD_TYPE=Debug -DDISMOUNT_BUILD_TESTS=ON && make -j8
python3 tests/riscv/run_compat.py                      # out/compat-riscv-rv64, out/compat-riscv-rv32
python3 tests/riscv/run_compat.py --arch rv32 --file zba
python3 tests/riscv/tools/fuzz_decode.py --count 200000 --seed 1
python3 tests/riscv/tools/fuzz_roundtrip.py --count 100000
python3 tests/riscv/tools/gen_support_matrix.py        # tests/riscv/SUPPORT.md
python3 tests/ia32/tools/compare_reports.py out/compat-riscv-baseline-rv64/report.json out/compat-riscv-rv64/report.json
```

## LLVM behavior that looks odd (matched on purpose)

- The CSR names are printed whichever features are enabled (LLVM 23 has no
  feature check in the printer); the h halves (`cycleh`...) are RV32 only.
- llvm-objdump decodes Zicsr, Zifencei, the hint aliases (`ntl.*`, `pause`,
  `lpad`, `prefetch.*`) and `rdtime` and the like whichever features are on.
  sspush, sspopchk and ssrdp (and c.sspush / c.sspopchk) print with Zimop (and
  Zcmop) only; the encodings of mop.r.28 / mop.rr.7 with rd = x0 which are not
  sspopchk / sspush are invalid.
- The compressed hints print as themselves (`c.addi a0, 0`, `c.li zero, 3`,
  `c.nop 3`, `c.ntl.p1`), the other compressed instructions print the 32 bit
  instruction they expand to, and `c.mv a0, a1` prints `mv a0, a1` while
  `add a0, zero, a1` stays `add`.
- `-M no-aliases` prints the `dyn` rounding mode, the default format leaves it
  out; the conversions which never round never print `rne`.
- The decoder accepts `aes64ks1i` round numbers 11-15 which the assembler rejects.
- Unknown units are skipped as objdump does: 2 bytes for a 16 bit parcel, 4 for a 32
  bit word, 6 / 8 / 10-22 bytes for the longer formats, 1 byte for the reserved one.
- llvm-mc: `zext.h`, `zext.w`, `sext.b` and `sext.h` without their extension are
  a pair of shifts; `tail` jumps through `t2` with Zicfilp and through `t1`
  otherwise; `addiw rd, zero, imm` and `add rd, rs, zero` are compressed to `c.li`
  and `c.mv`; a branch to `.+N` out of range is relaxed to the opposite
  branch and a `jal`; the uppercase rounding modes, fence sets and `0X10` are
  rejected; the registers of the compressed instructions are lowercase.
- `li` follows LLVM's RISCVMatInt, with the Zba (SLLI.UW, SH*ADD), Zbs (BSETI,
  BCLRI), Zbb (RORI) and Zbkb (PACK) variants and the two ADDI trick.
  A few 64 bit constants (about 1 in 10^4 random ones) take another sequence
  than LLVM's: see SUPPORT.md.
